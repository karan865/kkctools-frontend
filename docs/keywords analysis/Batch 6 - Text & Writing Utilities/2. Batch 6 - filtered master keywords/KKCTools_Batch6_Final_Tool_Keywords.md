> **Selection rule:** only keywords a brand-new DA 1 site can realistically push into the **top 10** (same filter as Batch 5). Everything else is listed with the reason.  
> **SERP data:** ⏳ none yet for Batch 6 — rank chances are judged from keyword data and known SERP owners; confirm with the SERP pull in Section 6

## How keywords were selected (DA 1 filter)

1. **Primary KD ≤ 15**, or a long-tail cluster where most rows are KD ≤ 20 and one engine-built table answers all of them.
2. **The tool must work 100% in the browser.** Grammar checkers, paraphrasers and rewriters need AI or a language model. That breaks our zero-network rule, and a weaker rule-based version would not hold a top-10 spot, so they are not selected even with KD 5–11.
3. **No brand intent** (Grammarly, QuillBot, WordCounter.net).
4. **No thin pages:** long tails like “how many pages is 1,500 words” are answered by **one** page with a generated table, never one URL per number.

**Rank chance:** ✅ good = exact tool term or long tail at KD ≤ 15 with no single dominant site · 🟡 possible = exact-match domains or KD 16–29 in the way; needs links and a better tool.

## What these exports tell us (read first)

- **Neither seed head is in the files.** `word counter` and `character counter` are missing (KD > 30). Easy variants are present (`characters counter` 6,600 / KD 0, `word counter free` 4,400 / KD 3).
- **The real prize is the long tail:** “how many pages is X words” (~100,000 combined) and “how many words is X characters” (~30,000, mostly rising). Small sites rank for these today.
- **The biggest single numbers are AI tools** (grammar, punctuation, paraphrase, rewrite). They are not selected; see rule 2.
- **Many rows are declining.** AI answers and Google’s own answer boxes take simple “how many words / pages” questions, so expect fewer clicks than the volumes. A page with a working tool plus a full table still wins clicks the answer box cannot satisfy (custom font, spacing, paste text).
- **Low YMYL risk**, and the tools share one text engine, so the whole batch is cheap to build.

## How to read the tables

- **Role:** Primary = the page’s main target · Secondary – easy = KD ≤ 15 · Secondary – medium = KD 16–24 · Support = KD 25–30, use in H2 / FAQ.
- **Intent** (Semrush codes, decoded as 0 = Info, 1 = Nav, 2 = Comm, 3 = Trans).
- **Trend:** ⚠ irregular = 4+ months at zero · ⚠ declining = last 3 months under half of the first 3 · ↑ rising = last 3 months over 1.6× the first 3.
- **Long-tail rows** (“… queries (N phrases)”) sum many near-identical searches answered by one table on the page.
